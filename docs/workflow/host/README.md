# Host-reference indexing and the initial host-handling route

[Workflow index](../README.md) · [Source rules](../../../workflow/rules/host.smk)

Index host genomes and exercise the original host-handling implementation.
Host DNA dominates these sequencing libraries, so removal or selection of reads
changes the material available to downstream discovery.

## Inputs and products

Inputs are trimmed read pairs, Kraken-selected read pairs, host-route metadata
and the audited Physalia/Nanomia reference FASTAs from
[config/config.yaml](../../../config/config.yaml). BWA indexes are stored in
`data/results/reference_indices/{route}/`; initial handled pairs and yield metrics
are in `data/results/host_handling/`.

## Steps and rules

1. `make_fixture_reference` creates a one-million-base excerpt of each host
   reference for fixture tests only.
2. `index_host_reference` creates the five BWA index files and records the source
   reference. Production uses the complete audited reference genome.
3. `host_handling` retains pairs with both mates unmapped to the host where a
   reference exists; its original reference-free branch uses Kraken-classified
   pairs. Metrics and provenance record the route and retained yield.

## Interpretation and handoff

This original reference-free selection is retained for the smoke test. The accepted
cohort assembly route is implemented separately in
[phase3_cohort.smk](../phase3_cohort/README.md): reference-free libraries use a
fixed-effort subset of all trimmed reads. Do not infer the production assembly
strategy from the `host_handling` rule alone.

`index_host_reference` is reused by the benchmark and accepted cohort route.
The displayed fixture graph covers every rule here, including the miniature
reference producer. It is not a graph of the accepted 205-library assembly route.
See the [benchmark](../phase3/README.md) for the comparison behind that decision.

## Preview, launch and rule graph

Run from the repository root after the [shared environment setup](../README.md#environment-and-inputs).
The preview evaluates dependencies without executing analysis jobs. The launch
command submits the same scope through the existing cluster controller.
This scope can build missing upstream products; it is not restricted to this one rule file.

```bash
# Preview only.
snakemake phase1_ready phase1_smoke \
  --snakefile Snakefile --configfile tests/config.fixture.yaml \
  --cores 1 --dry-run --rerun-triggers mtime

# Execute this scope on the cluster (not needed to view or regenerate graphs).
bash scripts/submit_workflow.sh 'phase1_ready phase1_smoke' tests/config.fixture.yaml
```
