# Record inputs and validate the initial workflow

[Workflow index](../README.md) · [Source rules](../../../workflow/rules/validation.smk)

Preserve the analysis inputs and check that the initial workflow produces
consistent, accounted-for files. A completion marker indicates that a validator
finished successfully; it does not establish a biological association.

## Inputs and products

Inputs include the manifest, its checksum freeze, normalized sample table,
configuration, and initial per-library screen/host-handling outputs.
The configuration snapshot is in `data/results/provenance/run/`; production
readiness is recorded in `data/results/stages/phase1.ready`.
The fixture substitutes `tests/work/` for `data/results/`.

| Rule | Check or record | Product |
| --- | --- | --- |
| `snapshot_run_configuration` | Save configuration, sample table, manifest freeze and input checksums | `provenance/run/` |
| `phase1_ready` | Check sample/manifest consistency and expected input configuration | `stages/phase1.ready` |
| `validate_sample` | Check trimmed pairs and each initial screen/host-handling product | `validation/samples/{sample}.json` |
| `phase1_smoke` | Combine per-library checks and confirm expected studies/host routes | `stages/phase1_smoke.done` |

## Scope and handoff

The graph requests both `phase1_ready` and `phase1_smoke` using the three-library
fixture configuration, so all four rules are represented. The smoke target alone
does not depend on the separate readiness validator. These tests use real read
subsets and tiny reference excerpts. They do not substitute for the later
[cohort screen validation](../phase2/README.md), assembly checks or catalog checks.

Production `all` resolves only to readiness; its separate generated graph is in
[shared configuration](../common/README.md). The historical
[operation guide](../../../WORKFLOW.md) explains controller recovery and validation
records. Regenerating documentation does not rewrite any readiness marker or freeze.

## Preview, launch and rule graph

Run from the repository root after the [shared environment setup](../README.md#environment-and-inputs).
The preview evaluates dependencies without executing analysis jobs. The launch
command submits the same scope through the existing cluster controller.
This scope can build missing upstream products; it is not restricted to this one rule file.

```bash
# Preview only.
snakemake phase1_ready phase1_smoke \
  --snakefile Snakefile --configfile tests/config.fixture.yaml \
  --cores 1 --dry-run --rerun-triggers mtime

# Execute this scope on the cluster (not needed to view or regenerate graphs).
bash scripts/submit_workflow.sh 'phase1_ready phase1_smoke' tests/config.fixture.yaml
```
