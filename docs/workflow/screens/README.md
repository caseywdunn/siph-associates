# Screen reads for candidate associates

[Workflow index](../README.md) · [Source rules](../../../workflow/rules/screens.smk)

Apply three complementary screens to every included library before choosing
which genomes or markers to investigate. Their taxonomic suggestions are
**candidate nominations**, not accepted organism-presence calls.

## Inputs and products

All screens use the same quality-filtered paired reads from
[preprocessing](../preprocess/README.md), with tool and database locations in
[config/config.yaml](../../../config/config.yaml). Persistent products are under
`data/results/screens/`; each screen also writes a command/provenance record.
The database paths must be available on the cluster before execution.

| Rule | What it measures | Principal products |
| --- | --- | --- |
| `kraken_bracken` | Kraken2 sequence classification followed by Bracken genus/species estimates | `kraken/{sample}.report.tsv`, compressed assignments and classified read pairs; `bracken/{sample}.{G,S}.tsv` |
| `sylph_screen` | Genome-sketch matches to GTDB r220 and OceanDNA | `sylph/{sample}.profile.tsv` |
| `phyloflash_screen` | Small-subunit ribosomal RNA (SSU) reads, assemblies and classifications against SILVA | `phyloflash/{sample}.tar.gz` |

Bracken uses a 150-base read-length model and a threshold of ten in the locked
configuration. The wrappers and environments are linked directly from the
[source rule file](../../../workflow/rules/screens.smk); phyloFlash has a separate
legacy tool environment, with its Python wrapper run outside that environment.

## Interpretation and handoff

[Phase 2](../phase2/README.md) validates and pools these outputs. Only qualifying
sylph genome matches nominate additional public mapping references in
[Phase 4](../phase4_catalog/README.md). Bracken and phyloFlash do not independently
add genomes to that catalog. phyloFlash archives also provide SSU evidence for the
[eukaryote analysis](../eukaryote_gate/README.md).

The graph includes the eight-library pilot and 205-library cohort targets. They
share screen products; each rule is drawn once even though it runs for many
libraries. Separate quality-control and aggregation nodes are defined in Phase 2.

## Preview, launch and rule graph

Run from the repository root after the [shared environment setup](../README.md#environment-and-inputs).
The preview evaluates dependencies without executing analysis jobs. The launch
command submits the same scope through the existing cluster controller.
This scope can build missing upstream products; it is not restricted to this one rule file.

```bash
# Preview only.
snakemake screen_pilot screen_cohort \
  --snakefile Snakefile --configfile config/config.yaml \
  --cores 1 --dry-run --rerun-triggers mtime

# Execute this scope on the cluster (not needed to view or regenerate graphs).
bash scripts/submit_workflow.sh 'screen_pilot screen_cohort' config/config.yaml
```
